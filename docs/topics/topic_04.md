# Chapter 04: Document Ingestion Pipelines, Chunking Strategies & Token Granularity Dilemmas

> Part of the **RAGA Architecture & Systems Engineering Reference Manual**.

Document ingestion forms the critical foundation of any retrieval pipeline, dictating the ceiling of downstream search accuracy and generative grounding. The primary challenge in designing ingestion workflows is navigating the token granularity dilemma: selecting chunk boundaries that are small enough to ensure vector distinctiveness, yet large enough to preserve semantic context. In naive systems, static character or token counts are applied uniformly across heterogeneous text, frequently splitting crucial thoughts mid-sentence.

To overcome these limitations, modern ingestion pipelines employ structure-aware decomposition. Documents are initially parsed into structural trees comprising headings, sub-headings, paragraphs, lists, and code blocks. By honoring natural semantic divisions, the pipeline ensures that logically unified sections remain intact during subsequent chunking stages. This structural preservation is particularly vital when indexing technical documentation, legal contracts, or scientific literature where context is hierarchical.

RAGA implements a hierarchical dual-stage chunking strategy. During the primary stage, raw texts are partitioned into large parent nodes of approximately 1,000 characters with an intentional overlap of 100 characters. These parent nodes represent coherent, self-contained units of information capable of supplying the language model with sufficient background context. Each parent node is assigned a unique UUID and stored in a local, indexed document repository.

In the secondary stage, each parent document is recursively partitioned into smaller child chunks of approximately 200 characters with a 50-character overlap. These child chunks serve exclusively as dense and sparse retrieval keys. Because small child chunks focus on specific statements, technical terms, or code snippets, their embedding vectors remain crisp and uncontaminated by extraneous surrounding prose, resulting in high vector search specificity.

Token boundary management requires careful handling to prevent truncated words and broken syntax. RAGA enforces whitespace and sentence-boundary snapping within its character-level splitting logic. When calculating chunk slices, the algorithm adjusts the step size to ensure that chunk overlaps never exceed or equal the base chunk size, thereby avoiding infinite indexing loops and redundant slice duplication.

Metadata tagging during ingestion is essential for downstream observability and parent document linking. Every child chunk generated by RAGA is enriched with rich metadata attributes, including `parent_id`, `child_index`, `parent_index`, `source`, and timestamp. This bidirectional link ensures that regardless of which child chunk matches a user's query, the retrieval engine can instantly resolve the full parent node without scanning the entire corpus.

Through this structured ingestion pipeline, RAGA balances the competing demands of retrieval sensitivity and generative depth. Child chunks provide the high-resolution search indices necessary to identify relevant material, while parent nodes supply the broad context required for coherent generation. This multi-tiered ingestion methodology serves as a robust foundation for enterprise retrieval.
