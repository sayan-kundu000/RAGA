# Chapter 01: High-Level Architecture of RAGA & Production-Grade Agentic Systems

> Part of the **RAGA Architecture & Systems Engineering Reference Manual**.

Modern enterprise Retrieval-Augmented Generation (RAG) applications have evolved significantly beyond naive vector similarity pipelines, which frequently suffer from hallucinations, irrelevant context injection, and high token costs. The RAGA system addresses these shortcomings through an integrated, multi-stage architecture combining hierarchical document decomposition, dual-pathway hybrid retrieval, neural cross-encoder reranking, and multi-session semantic memory. At its core, the system decouples the granularity of text indexing from the breadth of context supplied to the language model, resolving the fundamental tension between retrieval precision and generative coherence.

The lifecycle of a user request in RAGA begins at the asynchronous FastAPI boundary, where incoming queries are ingested alongside persistent user identifiers and session tokens. Concurrently with request validation, an automated declarative fact extractor parses the conversational turn to identify latent user preferences, programming language affinities, and stylistic constraints, persisting them to a semantic profile store. This dynamic memory ingestion loop operates asynchronously to guarantee zero cold-start latency for the current turn while priming future turns for tailored personalization.

The retrieval pathway executes a dual-index lookup across sparse lexical and dense semantic representations. The dense pathway utilizes cosine similarity across high-dimensional vector spaces to capture nuanced semantic intent and conceptual synonymy, while the sparse pathway computes Okapi BM25 scores over inverted index term postings to retain exact keyword and identifier fidelity. By running both lookups against small, granular child chunks, the system avoids vector dilution often caused by long, heterogeneous documents.

Once candidate lists are generated by both pathways, Reciprocal Rank Fusion (RRF) merges them into a single, unified priority queue. Unlike linear score blending, which requires sensitive scaling and calibration, RRF operates strictly on reciprocal rank positions, ensuring robust fusion regardless of differing underlying score distributions. Top-ranking child hits are then mapped back to their respective parent document nodes via a persistent local document store, swapping narrow chunks for rich, explanatory surrounding context.

Because parent document expansion can significantly increase prompt size, candidate documents are immediately passed through Cohere ReRank v3 context compression. This cross-encoder model evaluates query-document token interactions simultaneously, applying deep multi-head attention to score exact relevance. Chunks that fail to satisfy a minimum relevance score threshold are pruned immediately, drastically lowering prompt token consumption and suppressing distractor context before generation.

The generative loop receives the pruned, high-signal parent passages alongside a customized system prompt generated by the persona adapter. The adapter injects known user facts into the system instruction block, directing the LLM to modulate its output format—such as strictly returning executable Python code without conversational pleasantries when requested by the user. Sub-millisecond latency telemetry monitors every stage of the execution lifecycle, recording retrieval, reranking, and generation metrics.

By formalizing this multi-tiered pipeline into a decoupled modular service, RAGA achieves a high standard of architectural resilience and maintainability. Each stage can be scaled, modified, or benchmarked independently, allowing engineering teams to swap embedding models, alter vector backends, or adjust compression thresholds without destabilizing the broader production service. The resulting architecture serves as a production-grade blueprint for low-latency, personalized retrieval agents.
